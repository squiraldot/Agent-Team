# Content Playbook

## Goal
Create useful, accurate technical content with a clear audience and a traceable evidence trail.

## Inputs
- Audience and their current knowledge
- Problem or question to solve
- Format: thread, article, tutorial, or short video script
- Desired length and call to action
- Claims that need fresh verification

## Workflow
1. Planner defines audience, promise, angle, and acceptance criteria.
2. Researcher gathers primary sources and checks dates/version compatibility.
3. Builder creates an outline, then a draft with concrete examples.
4. Reviewer checks factual claims, copied phrasing, code correctness, clarity, and unsupported hype.
5. Builder incorporates approved corrections.
6. Human owner approves publication; do not auto-publish.

## Quality gate
- Every time-sensitive or non-obvious technical claim has a source.
- Code examples include prerequisites and expected behavior; label untested code.
- Headline promises match the body.
- Clearly distinguish fact, opinion, and speculation.
- No invented quotes, statistics, screenshots, or citations.
- Avoid close paraphrase of a single source; use original explanation and cite it.

## Output
Draft; title options; source list; verification notes; open questions; publication checklist.
