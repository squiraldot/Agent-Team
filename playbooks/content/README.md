# Content Production Playbook

## Purpose

Create useful, accurate technical content for a defined audience while preserving an inspectable evidence trail. Suitable outputs include articles, tutorials, social threads, newsletter drafts, and video scripts.

## Required inputs

- Audience and their existing knowledge.
- Reader problem or question and the promised outcome.
- Format, length, channel, language, tone, and call to action.
- Brand constraints, accessibility needs, and prohibited claims.
- Freshness requirements and primary sources, if already known.
- Approval owner and publication destination.

If an input materially changes the result and cannot be safely assumed, ask one focused question.

## Workflow

1. **Plan:** define audience, user problem, angle, key takeaway, non-goals, and acceptance criteria.
2. **Research:** identify verifiable claims; prefer official docs/specifications, release notes, and source code. Record URL, access date, product/version, and claim supported.
3. **Outline:** sequence the argument before drafting; distinguish facts, analysis, examples, and opinion.
4. **Draft:** explain concepts in plain language; use examples that are accurate and clearly labeled.
5. **Verify:** check dates, names, version details, commands, code, statistics, and all material claims against the source.
6. **Review:** use a reviewer to challenge misleading claims, missing context, plagiarism risk, accessibility, privacy, and brand fit.
7. **Finalize:** provide the draft, title options where useful, source list, unresolved caveats, and a copy-ready CTA.
8. **Publish only after approval:** do not post, email, or schedule externally without explicit authorization.

## Quality gates

- The title and hook match the actual content.
- Every material factual claim is supported or explicitly labeled as opinion/assumption.
- Technical commands and code are tested when feasible; untested examples are marked.
- No fabricated testimonials, screenshots, benchmarks, quotes, or citations.
- Copyrighted text is not reproduced beyond appropriate brief quotations.
- The piece is readable, accessible, and useful without clickbait or false urgency.
- CTA, sponsorship, affiliate relationship, and material limitations are disclosed when relevant.

## Failure handling

If a source is unavailable, do not invent its contents. Use a second authoritative source or state the uncertainty. If claims conflict, describe the conflict and avoid false precision. If code cannot be run, label it untested and provide verification steps.

## Deliverables

- Final draft and alternative titles if requested.
- Evidence/source list.
- Audience and intended channel.
- Verification checklist with actual checks performed.
- Remaining uncertainties and approval needed.
