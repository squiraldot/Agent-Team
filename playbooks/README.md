# Playbooks

Playbooks use YAML front matter (`name`, `description`, `version`, `owner`, `status`) and SemVer. Keep each workflow canonical and reference shared role/skill guidance.

Playbooks are repeatable end-to-end workflows. Each playbook should specify inputs, steps, quality gates, failure handling, and outputs.

- [Content](content/README.md): evidence-backed threads and articles.
- [Product](product/README.md): feature discovery, implementation, and validation.
- [Growth](growth/README.md): distribution experiments and offers.

See [templates](../templates/README.md) and the [five-minute extension guide](../docs/EXTENDING.md) when adding a workflow.

Use only the playbook relevant to the task; adapt it to the actual context rather than following it mechanically.
