# UI/UX Design Standards

## Principles
Start with user goals and evidence, not trends. Separate observation, hypothesis, and decision; never invent research. Cover loading, empty, error, offline, permission, and recovery states. Target WCAG 2.2 AA where applicable; do not claim conformance without testing.

## Process
Discover audience/tasks; research user evidence, platform conventions, and accessibility using ../../research/PROTOCOL.md; map flows and edge cases; sketch alternatives; specify responsive layouts, tokens, components, states and accessibility; validate; hand off using ../../templates/handoff-spec.md with independent QA.

## Quality checklist
- [ ] Goals and acceptance criteria trace to brief.
- [ ] Navigation, breakpoints, keyboard/touch and failure states specified.
- [ ] Focus, semantics, labels, contrast, zoom/reflow, motion and target size reviewed.
- [ ] Localization expansion and realistic content considered.
- [ ] Evidence, limitations, and reviewer decision explicit.

## Common pitfalls
Happy-path-only flows, color-only cues, tiny targets, hidden focus, placeholder copy, premature fidelity, trend copying, missing states, and claiming accessibility from contrast checks alone.
