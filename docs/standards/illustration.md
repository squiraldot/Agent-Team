# Illustration and Visual-Art Standards

**Status:** Active guidance. Revalidate by 2027-01-28.  
**Research protocol:** Follow [research/PROTOCOL.md](../../research/PROTOCOL.md). Sources accessed 2026-10-28. Exact generator capabilities, provenance, and licence terms are **UNVERIFIED** unless recorded for the specific tool/version and asset.

## Principles
- Translate the communication goal into a clear visual brief before drawing or prompting.
- Specify subject/action, composition, framing, lighting, palette, mood, detail, medium, aspect ratio, placement, and exclusions.
- Maintain a coherent visual grammar across an asset family with purposeful variation.
- Use approved references; record provenance and avoid exact imitation of a living artist or copying protected characters/marks.
- Specify crop-safe zones, alpha/background, dimensions, output format, text requirements, and post-production needs.
- Distinguish planned prompt, generated candidate, edited final, and approved asset. Never report a file delivered unless it exists and was inspected.
- Consider cultural context, representation, consent, accessibility, and meaningful text alternatives.

## Process
1. **Brief:** record audience, purpose, channel, ratio/dimensions, subject, must-have details, exclusions, style continuity, rights, and approver.
2. **Research:** consult approved references and exact tool documentation; log URL, access date, tool/model/version if known, licence, and uncertainty.
3. **Art direction:** define palette, shape language, line/texture, lighting, perspective, detail density, and variation rules.
4. **Prompt/spec:** use [image brief template](../../templates/image-brief.md); separate factual requirements from aesthetic preferences and negative constraints.
5. **Create:** generate/draw candidates with settings where available. Do not imply a tool ran if only a prompt was written.
6. **Inspect:** check geometry, continuity, text, artifacts, crop, contrast, transparency, size, and rights/similarity risks.
7. **Refine/export:** record manual repair, cleanup, vectorization, background removal, compression, and requested variants.
8. **Handoff:** inventory existing files, label concept vs final, include available source files, and list remaining defects and approvals.

## Quality checklist
- [ ] Brief states use, audience, composition, palette, ratio, format, and exclusions.
- [ ] Asset family follows approved visual grammar and each variation has a purpose.
- [ ] Focal point, silhouette, contrast, and crop-safe area work at target size.
- [ ] Image text is checked character-by-character; use editable typesetting when exact copy matters.
- [ ] Transparent background is actual alpha, not checkerboard artwork.
- [ ] No obvious artifacts, unwanted watermarks/logos, or unintended likenesses.
- [ ] Reference rights, tool/model/version, edits, and filenames are recorded where known.
- [ ] Alt text/long description is supplied when informative; decorative status is explicit.
- [ ] Exports match requested dimensions, format, transparency, and compression; editability limits are clear.

## Common pitfalls
Vague prompts; conflicting style references; expecting exact typography or diagrams without inspection; calling a prompt an image; calling a flat raster layered/vector/editable; ignoring crop, rights, culture, alt text, continuity, or post-production; assuming a generated result is accurate or commercially cleared.
