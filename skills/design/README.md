# Design Skill

## Purpose

Design useful, accessible, maintainable interfaces and visual assets from user needs and verified constraints.

## Procedure

1. Define audience, job-to-be-done, context, platform, constraints, and success criteria.
2. Map information architecture and primary user flows before polishing visuals.
3. Establish hierarchy, spacing, type scale, color tokens, component rules, and interaction states.
4. Design mobile-first and test responsive behavior across representative viewports.
5. Include loading, empty, error, disabled, success, offline, and permission-denied states where relevant.
6. Check keyboard navigation, focus visibility, accessible labels, contrast, reduced motion, and readable content order.
7. Use real assets and respect licenses; do not fabricate product screenshots, endorsements, or customer logos.
8. Consider performance, localization, text expansion, and long/short content.
9. Review the design against acceptance criteria and user context.
10. Document assumptions and what requires user testing.

## Quality checklist

- Primary action and page purpose are obvious.
- Layout adapts without horizontal overflow or inaccessible controls.
- Color is not the only way to communicate status.
- Interactive states and error recovery are specified.
- Typography and contrast support readability.
- Components use consistent spacing and semantic hierarchy.
- Animations respect reduced-motion preferences and do not block tasks.
- Assets are optimized and have appropriate rights.
- Design choices support the user task rather than decoration alone.

## Handoff

Provide annotated screens or specification, tokens/components, interaction behavior, responsive notes, accessibility checks, asset sources/licensing, and open questions. Do not claim usability validation unless real testing occurred.
